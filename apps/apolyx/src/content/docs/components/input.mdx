## Usage

```tsx
<Label htmlFor="email">Email</Label>
<Input id="email" type="email" autoComplete="email" />
```

`Input` is the bare native control. Reach for [Field](/docs/components/field) when you want the label, help text and errors wired for you, and [Input Group](/docs/components/input-group) when the box needs icons, text or buttons inside it.

## Basics

Default, disabled and read-only. Read-only keeps the value selectable and focusable but drops the editing affordance.

## Sizes and variants

### Sizes

`size` is `sm` (32px), `md` (40px, default) or `lg` (44px). The native `size` attribute is still available as `htmlSize`.

<ComponentPreview name="input-sizes-demo" />

### Variants

`outline` (default) is a soft **borderless** pad that blooms a ring on focus — the same surface Field and Input Group use. `filled` is a stronger muted fill; `underline` keeps a bottom rule with a centre-out focus bar; `ghost` is transparent until hover. Add `shape="pill"` for search-style inputs.

## When to use what

| You need | Use |
| --- | --- |
| A bare control you label yourself | `Input` + `Label` |
| Label, help text, errors and a counter | `Field` + `FieldInput` |
| Icons, prefixes, suffixes or buttons inside the box | `InputGroup` |
| A password with show/hide and strength | `PasswordInput` |
| Numbers with steppers | `NumberInput` |
| One-time codes | `InputOTP` |
| Phone, card or date formats | `MaskedInput` |

## Accessibility

- Always pair with a `Label` (or `aria-label`).
- Set `aria-invalid` and `aria-describedby` for errors.
- Use the right `type`, `inputMode` and `autoComplete` so mobile keyboards and password managers help.
