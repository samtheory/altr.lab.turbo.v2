## Usage

```tsx
<Timeline defaultValue={2} aria-label="Release history">
  <TimelineItem step={1}>
    <TimelineSeparator />
    <TimelineIndicator />
    <TimelineHeader>
      <TimelineDate>Mar 2026</TimelineDate>
      <TimelineTitle>Project initialised</TimelineTitle>
    </TimelineHeader>
    <TimelineContent>Repository and CI are in place.</TimelineContent>
  </TimelineItem>
  {/* …more items */}
</Timeline>
```

## Anatomy

`Timeline` (an `<ol>`) → `TimelineItem` (an `<li>`) → `TimelineSeparator` + `TimelineIndicator` + `TimelineHeader` (`TimelineDate`, `TimelineTitle`) + `TimelineContent`.

Indicator and separator are positioned from the item, so their order inside it does not matter. The rail geometry lives in CSS variables on the root (`--tl-indicator`, `--tl-gap`, `--tl-rail`, `--tl-offset`), which is why every layout below is a prop rather than a pile of class overrides.

## Progress

`value` is the **last reached step**. Each item derives its state from its `step`:

| State | When | Indicator | Line to the next item |
|---|---|---|---|
| `completed` | `step < value` | Filled with the tone | Filled |
| `current` | `step === value` | Filled + soft halo, `aria-current="step"` | Track only |
| `upcoming` | `step > value` | Hollow | Track only |

Items with `step <= value` also get `data-completed`, and every item exposes `data-state` for your own styling. `defaultValue` is `0` (nothing reached). The line fill animates when `value` changes and is instant under `prefers-reduced-motion`.

## Tokens used

`primary`, `success`, `warning`, `info`, `destructive`, `muted-foreground`, `border`, `background`, `duration-base`, `duration-slow`, `ease-out`, `radius`.

## Accessibility

- Renders a native ordered list, so screen readers announce position and count. Give the `Timeline` an `aria-label`.
- The current item gets `aria-current="step"`.
- Indicators and separators are decorative (`aria-hidden`). If state matters, say it in text too, for example a badge reading "failed", not only a red dot.
- Not interactive: there is no keyboard behaviour and no `onValueChange`. For a clickable flow, use a stepper pattern instead.
- Keep each `TimelineItem` a direct child of `Timeline`; the last item's separator is hidden with `:last-child`.
