Apolyx has no form component and no form library. Every recipe here is a native `<form>` built from kit parts: values come from `FormData`, submission runs through a React 19 action, and errors flow back into `Field`. Copy a recipe and replace the fake `wait()` with your request.

## The approach

```tsx
function useFormAction<S>(action: (prev: S, data: FormData) => Promise<S>, initial: S) {
  const [state, dispatch, pending] = useActionState(action, initial);
  const onSubmit = (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    const data = new FormData(e.currentTarget);
    startTransition(() => dispatch(data));
  };
  return { state, pending, onSubmit };
}

const { state, pending, onSubmit } = useFormAction(async (prev, data) => {
  const errors = validate(data);
  if (Object.keys(errors).length) return { status: "error", errors };
  await save(data);
  return { status: "success", errors: {} };
}, { status: "idle", errors: {} });

<form onSubmit={onSubmit} noValidate>
  <Field label="Email" error={state.errors.email}>
    <FieldInput name="email" type="email" />
  </Field>
  <SubmitButton pending={pending}>Save</SubmitButton>
</form>
```

- **Validation lives in the action** and returns `{ errors: Record<field, string | string[]> }`. An array renders as a list under the field.
- **Pending state** is the third value of `useActionState`. The submit button shows a spinner, disables itself and sets `aria-busy`.
- **Submit from `onSubmit`, not `<form action>`.** React resets a form after every action passed to `action`, failed or not. That clears what the user typed and desyncs controls that keep their own state, like `Checkbox` and `Switch`, whose hidden inputs revert while the visible control stays checked. Dispatching from `onSubmit` inside `startTransition` keeps the same pending and state handling without the reset.
- **Reset on success** by changing the form's `key`; that resets kit controls too.
- **Focus the first invalid control** after a failed submit: an effect queries `[aria-invalid="true"]` inside the form.
- `noValidate` turns off browser bubbles so errors look the same everywhere; keep `type="email"`, `autoComplete` and `inputMode` for keyboards and autofill.

The shared helpers (`useFormAction`, `SubmitButton`, `ErrorSummary`, `useFocusFirstInvalid`) are under 100 lines in the demo source, `form-shared.tsx`.

The default: one column, label above the control. The sign-up form above uses `PasswordInput` with `PasswordStrength`, and a `Checkbox` whose error is wired with `aria-describedby`.

## Flows

### Multi-step with verification and review

A horizontal `Timeline` shows progress (`value` is the last finished step). Each step is its own small form that validates on Continue; answers live in one parent state, so Back and Edit keep them. ## Using a form library

These recipes stay dependency-free on purpose. To add React Hook Form, keep the kit controls and connect them through `Controller` (or `register` for `FieldInput`) and pass `formState.errors[name]?.message` to `Field error`. For schema validation, run a Zod schema inside the action and map `error.flatten().fieldErrors` straight into `errors`. The array shape matches what `Field` already renders.
