# Shared engine — sharpening decisions

> Decisions for Jord before intent. Catalog: [[../2026-10-18-product-catalog]]. Intent: [[../../feature_list/Jord/00-intent]].

Chosen on 2026-10-18. Code does not start from this note.

## What we are building first

A single libSQL **file** inside this repo. `@altr/base` opens it. One Hono server, created later under `cloud/`, is the only new process. Artemis’s future AI bot uses this same file. Other database engines stay a seam in the design and are not installed.

## Counts

| | First slice | Later |
|--|-------------|--------|
| Cloud servers | **1** — `cloud/jord` (`@altr/jord-server`) when S0001 is built | A vector worker only after the bot needs its own process |
| Apps | **0** new apps. `apps/apolyx` stays the docs app | A studio app when the file and the API already work |
| Databases | **1** file, `data/jord.db` | Same driver can take a `libsql://` URL. Postgres is a second driver, not a second product |
| Cache, Mongo, websockets, auth | none | [[../../feature_list/Jord/01-later]] |

PocketBase stays in `cloud/pocketbase` and is not this database.

## Why a file

libSQL speaks SQLite and runs as a file (`file:./data/jord.db`). You carry the lab by copying that file. No Turso account, no Docker, no Postgres server. The same `@libsql/client` can point at hosted Turso later by changing the URL. `sqlite-vec` can be added on this file when the Artemis bot needs search. That is why this file is the right first store for the bot, and why a hosted-only database is the wrong start. Full layout: [[../../feature_list/Jord/02-architecture]].

The file is gitignored. The repo records the path and the schema. You carry the data file yourself so bot notes never land in git.

## Dialect seam

Drizzle owns the schema from the first slice, with the libSQL driver only. `DATABASE_URL` must be a `file:` URL. Any other scheme fails with a clear error until a later slice allows it. That is the flexibility: one schema module, one URL, drivers added when a plan says so.

## First table

`records`: `id`, `bucket`, `body`, `created_at`.

Artemis will use bucket `artemis` for bot rows. HyperFit and the others get their own buckets when those tracks are promoted. The first slice does not create a bot, a trading table, or an embedding column.

## Name

**Locked after this note: Jord**, with the later admin app named **Jord Studio**. The package stays `@altr/base`. Docs folders are `idea/Jord` and `feature_list/Jord`. The file path does not include the product name.

The brief is the same as **Lode**: a short name for a store in the ground, or for the one who keeps that store. Greek and Norse names were checked on 2026-10-18. The ones already used for databases, SQLite tools, or AI memory are listed under reject.

**Reject**

| Name | Why |
|------|-----|
| PolyBase | Microsoft SQL Server feature |
| AltrBase | Reads as the package `@altr/base` |
| Keel | Keel.sh is a backend product |
| Urd / Urðr | Already used for database reflection and for AI-agent memory |
| Mimir, Munin, Huginn | Grafana Mimir, Munin monitoring, Huginn agent |
| Leto | Mother of Artemis, but Letos is a SQLite desktop app |
| Fulla | `fulla.dev` is an identity server |
| Atlas, Iris, Hestia | MongoDB Atlas, InterSystems IRIS, HestiaCP |

**Chosen: Jord.** Jord Studio is the later admin app. The shortlist below is the record of what was compared.

| Rank | Name | Source | Why it fits |
|------|------|--------|-------------|
| 1 | **Jord** | Norse earth, mother of Thor | One syllable, same weight as Lode. The file is the ground the other products stand on. |
| 2 | **Idunn** | Norse keeper of the apple chest | She stores the thing the gods live on. Fits a file you carry, and later bot memory in that chest. `idunn.no` is a publisher, not a database. |
| 3 | **Omphalos** | Greek navel-stone at Delphi | The stone in the ground that marks the center. Closest myth to a lode. Three syllables. |
| 4 | **Plouton** | Greek god of wealth under the earth | The mine itself. Two syllables. Quieter than the Roman name Pluto. |
| — | **Lode** | English | Still the clearest non-myth word. Kept as the benchmark the myth names have to beat. |

Plinth and Cairn stay available and are not myth names. Clotho (the Fate who spins the thread) is a spare; an old lab project already used it for data schemas.

## Answered questions

1. Public name — shortlist above, not locked.
2. First table — `records` with a `bucket`, not a demo `notes` table and not Artemis positions.
3. Drizzle — yes in the first slice, libSQL driver only.
4. Auth — out of the first slice. The stub in `@altr/base/auth` stays a stub.
5. PocketBase — stays optional in the stack doc. It is not the engine.
6. Cache binary — undecided because cache is out of the first slice.
